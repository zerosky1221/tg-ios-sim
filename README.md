# Свежий Telegram для iOS в браузере на ПК

Схема такая: бесплатный Mac-сервер GitHub каждый день собирает Telegram для iOS из официальных исходников ([TelegramMessenger/Telegram-iOS](https://github.com/TelegramMessenger/Telegram-iOS)) и загружает сборку на [Appetize.io](https://appetize.io). Appetize запускает iOS-симулятор с этой сборкой прямо в браузере.

Ни Mac, ни iPhone для этого не нужны.

## Что понадобится (один раз)

1. **Аккаунт GitHub**: https://github.com/signup
2. **Аккаунт Appetize.io**: https://appetize.io. Бесплатного тарифа хватит, но минуты работы симулятора на нём ограничены.
3. **Свои `api_id` и `api_hash` от Telegram**: https://my.telegram.org/apps
   - Войдите по номеру телефона, нажмите «Create application» и заполните любое название, например `My iOS test`.
   - Скопируйте **App api_id** (число) и **App api_hash** (длинная строка).

## Настройка

### 1. Создайте репозиторий

На GitHub нажмите **New repository**:
- Название любое, например `tg-ios-sim`.
- Выберите **Public**: только для публичных репозиториев Mac-серверы GitHub бесплатны без ограничений по минутам. Ваши ключи всё равно хранятся в секретах, и посторонние их не видят.
- Поставьте галочку **Add a README file**.

### 2. Добавьте workflow

В репозитории: **Add file → Create new file**.
- Имя файла: `.github/workflows/telegram-ios-simulator.yml`
- Вставьте содержимое файла `telegram-ios-simulator.yml` из этой папки.
- Нажмите **Commit changes**.

### 3. Добавьте секреты

**Settings → Secrets and variables → Actions → New repository secret**. Создайте:

| Имя секрета | Что вписать |
|---|---|
| `TG_API_ID` | ваш api_id с my.telegram.org |
| `TG_API_HASH` | ваш api_hash с my.telegram.org |
| `APPETIZE_TOKEN` | API-токен из Appetize: Account → API token |

### 4. Запустите первую сборку

**Actions → Telegram iOS Simulator → Run workflow**.

Каждая сборка идёт долго, ориентировочно 1–3 часа. Кэш сборки специально не сохраняется: внутри него оказался бы ваш `api_hash`, а кэш публичного репозитория можно достать через pull request из форка.

### 5. Откройте Telegram

Когда сборка завершится (зелёная галочка), откройте её. Внизу, в разделе **Summary**, будет ссылка вида `https://appetize.io/app/...`. Откройте её на ПК и нажмите на экран телефона: запустится Telegram.

**Важно:** в Summary также будет код (`publicKey`). Сохраните его как секрет **`APPETIZE_PUBLIC_KEY`**. Тогда новые сборки будут обновлять то же приложение и ссылка не поменяется.

## Дальше всё автоматически

Каждый день в 06:00 по Москве workflow проверяет, появились ли новые коммиты в Telegram-iOS. Если появились, он собирает и обновляет приложение на Appetize. Если нет, сразу завершается.

Собрать вручную можно в любой момент: **Actions → Run workflow**.

## Что нужно знать

- **Насколько «свежие» обновления.** Telegram выкладывает исходники примерно вместе с релизами в App Store, иногда чуть позже. Это актуальная релизная версия, но не закрытые бета-версии из TestFlight.
- **Вход в аккаунт.** Вы входите по номеру, код придёт в ваш Telegram на других устройствах. Сборка работает на вашем собственном `api_id`, и Telegram иногда настороженно относится к входам через новые `api_id`. Надёжнее использовать второй аккаунт.
- **Каждая сессия Appetize может начинаться с чистого устройства**, и тогда войти придётся заново.
- **Не включайте `upload_artifact` в публичном репозитории без необходимости.** Внутри сборки лежит ваш `api_hash`, а artifact может скачать любой.
- **GitHub отключает ежедневный запуск**, если в публичном репозитории 60 дней не было активности. Тогда просто включите его снова на вкладке Actions.

## Если сборка упала

Откройте упавший шаг в логе.

- **«Telegram требует Xcode X, а на раннере его нет».** Telegram перешёл на новый Xcode, которого на серверах GitHub пока нет. Подождите, пока GitHub его добавит. Если в логе видно, что новый образ уже вышел (например, `xcode-28`), поменяйте `runs-on:` в файле.
- **Нехватка места или превышено время (6 часов).** Это ограничение бесплатного сервера. Попробуйте в файле заменить `runs-on: xcode-27` на `runs-on: xcode-27-xlarge`. Это более мощный сервер, но он платный даже для публичных репозиториев.
- **Ошибка в шаге «Сборка».** Скопируйте последние ~50 строк лога, и будем разбираться.
